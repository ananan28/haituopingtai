# 海拓商业版 0.1.5

## 消息记录与译文

新增主进程 SQLite 消息库，按服务器身份/演示身份分别建库。消息唯一键为渠道账号、渠道、会话、消息 ID；正文、元数据、原文摘要和译文共同保存在消息记录里。历史查询直接返回完整双语消息对象，不存在 DOM 缓存节点回贴步骤。

已接入当前平台自有演示会话：发送保存、重开恢复、分页历史与身份隔离。演示翻译仍明确是本地模拟，不代表已接真实收费模型。WhatsApp 官方网页还不能因此宣称已接入同一消息数据管道；官方渠道的数据适配仍需独立验收。

编辑原文会清除旧译文，延迟翻译按原文 SHA-256 比较更新，避免贴到已修改消息。重复收取相同消息不新增重复行，也不清除已有译文。

## Signal P4

- 新建独立 profile SQL 客户端，直接使用 Signal 原生 SQLCipher worker 协议。
- 每账号独立配置目录、加密数据库、OS safeStorage 加密的 SQL 密钥、worker、持久分区和渲染视图。
- 初始化去重、关闭/重开、取消未完成初始化、身份切换和未知发送方拒绝均由宿主注册表管理。
- 宿主服务直接处理 Signal 配置、语言资源、设置和 SQL IPC，不加载原普通版主进程，不创建旧窗口或启动旧子进程。
- 原应用 bundles/main.js 从商业版安装清单排除。
- RingRTC 原生资源由构建脚本从官方固定版本下载，校验归档与各文件 SHA-256；本地已有校验正确的文件则不联网。

本地 Electron 已验证两个真实 Signal 渲染器在一个宿主窗口内显示配对界面，没有额外窗口或未处理渲染错误。Windows 原生模块兼容性及 OS safeStorage 仍须 CI 实测。真实账号配对与端到端收发不能用数据库测试替代。

## 验证

本地已验证消息库持久化/双连接冲突/隔离、IPC 越权和身份切换，以及两个真实 Signal SQLCipher worker 的分离读写、加密、关闭重开和数据保留。

完整 Windows CI、真实 Signal 视图和最终包校验以对应构建结果为准。线上支付、真实模型计费和线上 Supabase 未操作。

## 可用入口

首页新增明确的“进入本机渠道工作区”按钮。默认离线演示保持零网络；用户主动进入本机工作区后，才可以打开真实网页或 Signal 账号视图。本机身份使用独立 local: 存储域，只获得本机渠道/外观等权限，服务器授权、员工后台、资金与真实 AI 翻译权限保持关闭。内置两个 Signal 账号入口供配对隔离验证。

## 商业版翻译边界

Signal 渲染层的旧免费翻译默认值、个人 API 字段和自动回译路径被宿主策略关闭；相关调用明确返回平台服务未接入。真实模型/计费未接入时，不通过旧普通版翻译引擎绕过字符服务，也不显示伪造的收费译文。
